Mailbox password change

An account with a real mailbox (created by signing in directly, not a local admin) doesn't have its own enMail password: its password IS the mailbox's password on your mail server. There's no standard IMAP/SMTP protocol for "changing the password" — each hosting panel has its own API. Setting this up in Settings → Mail server lets those users change it themselves from Settings → Profile instead of depending on someone logging into the panel to do it.

Is this required?

No. Without this, those users will see the "manage your password from the hosting panel" notice — enMail keeps working the same for everything else.

cPanel

  1. Go to cPanel → Security → Manage API Tokens → create a new token (you can restrict it to Email-only functions if your cPanel version supports it).
  2. In enMail, pick provider cPanel, fill in:
    • Panel URL: https://your-server:2083
    • Username: your cPanel username (not the mailbox's email)
    • API Token: the one you just generated

Plesk

  1. You need a Plesk admin user (the XML API only allows that role unrestricted).
  2. In enMail, pick provider Plesk, fill in:
    • Panel URL: https://your-server:8443
    • Username: admin
    • Admin password: that account's password

aaPanel

  1. In the aaPanel console: Panel Settings → API interface → turn it on. It'll show you an API Token (save it, it won't be shown the same way again).
  2. In the same panel, set the IP allowlist to the IP enMail will call from — don't use 0.0.0.0/0 (any IP) unless you fully understand the implication: that API isn't mail-only, it grants admin access to the whole panel.
  3. In enMail, pick provider aaPanel, fill in:
    • Panel URL: https://ip-or-domain:panel-port (the panel's own port, not the site's 80/443)
    • API Token: the one from step 1
If enMail runs on the same server as aaPanel

A Docker container doesn't see the host's 127.0.0.1 as its own localhost — for the IP to match aaPanel's allowlist, try the Docker bridge gateway IP (usually something like 172.17.0.1, check with ip addr show docker0 on the server) or the server's public IP.

After filling in the details, use the Test connection button before trusting it — it validates the credentials without touching any real mailbox.

aaPanel integration: not an officially documented API

Unlike cPanel and Plesk (which have public, documented APIs), this aaPanel integration calls an internal function of the installed mail plugin, reconstructed from its source code. A future aaPanel plugin update could change it — if "Test connection" starts failing after updating aaPanel, let us know so it can be reviewed.
