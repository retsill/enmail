Cambio de contraseña de buzones

Una cuenta con buzón real (creada iniciando sesión directo, no un admin local) no tiene una contraseña propia de enMail: su contraseña ES la del buzón en tu servidor de correo. No existe un protocolo estándar de IMAP/SMTP para "cambiar la contraseña" — cada panel de hosting tiene su propia API. Configurando esto en Ajustes → Servidor de correo, tus usuarios pueden cambiarla ellos mismos desde Ajustes → Perfil en vez de depender de que alguien entre al panel a hacerlo.

¿Es obligatorio?

No. Sin esto, esos usuarios van a ver el aviso "gestioná tu contraseña desde el panel de hosting" — enMail sigue funcionando igual para todo lo demás.

cPanel

  1. Entrá a cPanel → Security → Manage API Tokens → creá un token nuevo (podés restringirlo solo a funciones de Email si tu versión de cPanel lo permite).
  2. En enMail, elegí proveedor cPanel, cargá:
    • URL del panel: https://tu-servidor:2083
    • Usuario: tu usuario de cPanel (no el email del buzón)
    • API Token: el que acabás de generar

Plesk

  1. Necesitás un usuario admin de Plesk (la API XML solo admite ese rol sin restricciones).
  2. En enMail, elegí proveedor Plesk, cargá:
    • URL del panel: https://tu-servidor:8443
    • Usuario: admin
    • Contraseña de administrador: la de esa cuenta

aaPanel

  1. En el panel de aaPanel: Panel Settings → API interface → activalo. Te va a mostrar un API Token (guardalo, no se vuelve a mostrar igual).
  2. En el mismo panel, cargá el IP allowlist con la IP desde la que va a llamar enMail — no uses 0.0.0.0/0 (cualquier IP) salvo que sepas bien la implicancia: esa API no es solo de correo, da acceso de administración a todo el panel.
  3. En enMail, elegí proveedor aaPanel, cargá:
    • URL del panel: https://ip-o-dominio:puerto-del-panel (el puerto propio del panel, no el 80/443 del sitio)
    • API Token: el del paso 1
Si enMail corre en el mismo servidor que aaPanel

Un contenedor Docker no ve 127.0.0.1 del host como "localhost propio" — para que la IP le cierre al allowlist de aaPanel, probá con la IP de la puerta de enlace del bridge de Docker (normalmente algo como 172.17.0.1, revisá con ip addr show docker0 en el servidor) o con la IP pública del servidor.

Después de cargar los datos, usá el botón Probar conexión antes de darlo por hecho — valida las credenciales sin tocar ningún buzón real.

Integración con aaPanel: no es una API oficial documentada

A diferencia de cPanel y Plesk (con APIs públicas y documentadas), esta integración con aaPanel llama a una función interna del plugin de correo instalado, reconstruida a partir de su código fuente. Una actualización futura del plugin de aaPanel podría cambiarla — si "Probar conexión" empieza a fallar después de actualizar aaPanel, avisá para revisarlo.
